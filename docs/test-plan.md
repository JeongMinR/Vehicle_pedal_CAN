# 단계별 시험 계획

실제 제동 장치를 연결하기 전에 각 단계를 통과해야 합니다. 시험은 고정된 벤치 환경에서 수행하고, 전원 차단 또는 독립적인 비상 정지 수단을 즉시 사용할 수 있어야 합니다.

## 1. 센서 노드 단독 계측

- 센서 노드에서 가변저항 입력 범위와 방향(증가/감소)을 측정합니다.
- 여러 입력 속도로 가변저항을 움직이고, 원시 입력과 센서 노드 타임스탬프/순번을 기록합니다.
- 제동 버튼의 눌림/해제 논리, 접점 방식, 입력 전기 범위를 센서 노드 기준으로 확인합니다.
- 정상 범위, 노이즈, 반복성, 단선·단락 시 관측값을 기록합니다.
- 센서 입력이 센서 노드 ADC/GPIO 허용 범위를 벗어나지 않는지 확인합니다.
- 센서 노드가 CAN 센서 상태 프레임을 올바르게 발행하는지 모의 수신기에서 확인합니다.

## 2. STM32 CAN 수신 및 판정

- CAN 프레임 ID/DLC/필드 범위/순번/시간/유효성 검사 결과를 확인합니다.
- 정지 상태, 느린 변화, 급격한 변화에서 센서 시간 간격을 반영한 변화율 계산을 확인하고 결과를 `data/processed/`에 기록합니다.
- 필터 지연, 임계값, 판정 지속 시간, 해제 조건은 측정 근거와 함께 정합니다.
- 경계값 근처에서 출력이 반복 전환되지 않는지 시험합니다.
- CAN 프레임 재생으로 제동 버튼과 급가속 조건을 각각/동시에 발생시켜 제동 우선 판정을 확인합니다.

## 3. CAN 통신 (실제 구동부 미연결)

- 승인된 명세로 센서 노드→STM32 `SENSOR_STATUS` 수신과 STM32→모의 RC카 노드 `BRAKE_REQUEST` 송신을 확인합니다.
- 양방향 CAN ID, 데이터 길이, 스케일/바이트 순서, 주기, 카운터를 검증합니다.
- 버스 분리, 잘못된 프레임, 수신 지연 상황을 재현하고 오류 감지를 확인합니다.
- 시험 중 실제 RC카 제동/모터 구동 장치에 연결하지 않습니다.
- CAN 송신 요청과 실제 출력은 별개로 유지하고, 모의 노드에서 우선순위 상태만 검증합니다.

## 4. 통합 벤치 시험

- 제동 측 제조사 명세와 승인된 안전 절차가 확보된 뒤 진행합니다.
- 출력은 부하를 안전하게 고정한 시험 장치에서 확인합니다.
- 센서 오류, STM32 리셋, CAN 단절, 전원 저하 시 상태를 확인합니다.
- 시험 조건, 기대 결과, 실제 결과, 펌웨어 버전을 기록합니다.
